# CyberVPN: комплект ТЗ и production-схема Remnawave 2.8.0

В комплект входят:

1. [`TZ_Codex_Task1_Premium_Smart_RU_Remnawave_2_8_0.md`](TZ_Codex_Task1_Premium_Smart_RU_Remnawave_2_8_0.md) - нормативное ТЗ по исправлению и унификации Premium Smart RU.
2. [`TZ_Codex_Task2_SPB_Default_With_DE_Exceptions_Remnawave_2_8_0.md`](TZ_Codex_Task2_SPB_Default_With_DE_Exceptions_Remnawave_2_8_0.md) - нормативное ТЗ нового тарифа с SPB по умолчанию и DE-маршрутом для Antifilter/vendor/custom prefixes.
3. [`CYBERVPN_PREMIUM_SMART_RU_CURRENT_PRODUCTION_ARCHITECTURE.md`](../architecture/CYBERVPN_PREMIUM_SMART_RU_CURRENT_PRODUCTION_ARCHITECTURE.md) - подробный internal-only snapshot фактически развернутых настроек, границ доказательства, диагностики и rollback.
4. [`CyberVPN_Remnawave_2_8_0_TZ_manifest.json`](CyberVPN_Remnawave_2_8_0_TZ_manifest.json) - размеры, число строк и SHA-256 файлов комплекта.

ТЗ описывают требуемое поведение и не являются доказательством production-развертывания. Для текущего состояния сначала читать архитектурный snapshot, затем сверять его с final generated subscription и загруженным runtime. На текущем production Premium Smart RU имеет подтвержденные generated INCY/HAPP paths, восемь RAW/XHTTP transport paths и automatic regional failover в stable и canary-named responses: DE -> NL, Moscow -> SPB, затем regional `BLOCK`. Exact backend-owned JSON marker по-прежнему выбирает canary response identity, но stable и canary имеют одинаковую executable topology. Final Remnawave-generated bodies прошли normal, primary-down, all-down BLOCK и recovery; отдельно остается физическая phone-side INCY/HAPP TUN проверка. Task2 активирован после authoritative 13-community Antifilter artifact, DNS-only A ingress, dedicated RAW/XHTTP listeners, изолированного IPv6 bridge и production route matrix. Cloudflare token и exact A record проверены read-only, но Terraform import записи ожидает отдельные AWS/S3 remote-state credentials. Физическая Task2 device-side проверка также остается внешним evidence.

Уточнение 2026-07-14 supersedes прежнее чтение строк `torrent blocked` в ТЗ и evidence: torrent-каталоги/сайты не являются block-классом. В Task1 11 канонических каталогов (1337x, EZTV, Kinozal, LimeTorrents, NNMClub, RuTracker, Rutor, The Pirate Bay, TorrentDownload, TorrentGalaxy и YTS) идут через отдельный ранний `catalog-access-inline` в `World / EU`/DE до рекламы и других BLOCK rules; прочие сайты следуют обычной продуктовой маршрутизации. В Task2 каталоги следуют Antifilter/IP policy. Блокируется только распознанный BitTorrent protocol официальным Remnawave Node Plugin `torrentBlocker` по `https://docs.rw/learn/node-plugins/`; исторические torrent-domain/static fixture строки не являются acceptance proof для новой формулировки.

Документы намеренно не содержат customer credentials, subscription URLs, Reality keys, bridge secrets, invite codes и PII. Исходные ТЗ восстановлены в текущую рабочую папку из результатов исследования и приложенной production/target-архитектуры, поскольку первоначальные ссылки указывали на временные sandbox paths.
