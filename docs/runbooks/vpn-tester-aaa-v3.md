# CyberVPN VPN Tester AAA+ v3 Runbook

## Scope

VPN Tester AAA+ v3 validates Premium Smart RU routing, all tariff contracts, generated subscription dry-run artifacts, schedule gate execution, release-gate status, and read-only balancer recommendations.

The tester never logs raw subscription URLs, JWTs, cookies, private keys, Telegram initData, customer identifiers, or production VPN credentials. Evidence artifacts are JSON previews passed through backend redaction.

## Schedule Gate

Scheduled worker tasks call:

- `POST /api/v1/admin/vpn-tester/internal/schedules/{schedule_key}/run`

The backend is the only source of scheduling decisions. It checks:

- `VPN_TESTER_ENABLED`
- `VPN_TESTER_SCHEDULED_ENABLED`
- schedule existence
- schedule enabled state
- idempotency window

The backend records `last_checked_at`, `last_triggered_at`, `last_skipped_reason`, `last_status`, `last_run_id`, and `next_run_at` on `vpn_test_schedules`.

## Runtime Agent

The internal service `cybervpn-vpn-test-agent` exposes:

- `GET /health`
- `POST /internal/v1/runtime-checks`

The service is only attached to the internal backend network and requires `X-VPN-Test-Agent-Secret`. Production default is proxy-only/static safe checks:

- `VPN_TESTER_RUNTIME_ENABLED=false` makes runtime runs end as `skipped`.
- `VPN_TEST_AGENT_TUN_ENABLED=false` prevents TUN sandbox execution.
- No torrent, TOR, credential, or raw subscription traffic is generated by default.

## Release Gate Override

Persistent overrides are stored in `vpn_test_release_gate_overrides`.

Admin API:

- `POST /api/v1/admin/vpn-tester/release-gate/override`

Rules:

- reason minimum length is 20 characters;
- super admin TTL maximum is 1440 minutes;
- owner/super admin TTL maximum is 4320 minutes;
- active override is shown in `GET /release-gate`;
- expired overrides are ignored automatically.

## RBAC

Read endpoints allow `SERVER_READ` or `MONITORING_READ`.

Run create/cancel requires `SERVER_UPDATE` or `MANAGE_PLANS`.

Schedule mutation requires both `SERVER_UPDATE` and `MANAGE_PLANS`.

Tariff reads allow `SERVER_READ`, `MONITORING_READ`, or `MANAGE_PLANS`; commercial fields are hidden for roles without `MANAGE_PLANS`.

## Rollback

Application rollback:

1. Set `CYBERVPN_IMAGE_TAG` to the previous release tag in the stage1 compose `.env`.
2. Run `docker compose up -d cybervpn-backend cybervpn-admin cybervpn-worker cybervpn-scheduler`.
3. Confirm `https://api.cyber-vpn.net/healthz` and `https://admin.cyber-vpn.net/ru-RU/login`.

Database rollback:

1. Stop scheduler and worker first if the rollback target does not understand v3 schedules.
2. Run `alembic downgrade 20260701_vpn_tester_aaa_v2`.
3. Runtime `skipped` run statuses are converted to `degraded` during downgrade so the v2 status check remains valid.

Do not enable TUN sandbox or synthetic production users without a separate approved production change.
